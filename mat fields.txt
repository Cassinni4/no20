offsets from material base
(bN = bit N of that word, b2-3 = bits 2 and 3)
names are what `material <file> <n>` prints and what `new-material ___ name=value` takes
default = what a new material starts with (most common value over all game mats)

types
  u32   32-bit word (flags, packed color)
  u8   byte
  s16   signed 16-bit
  f32   float
  tex   texture slot (s32), -1 = no texture
colors are 0xAABBGGRR (bytes: R, G, B, A)



---shading---
the game builds a shader from these at load and they gotta agree with the mesh's vertex data
new-material refuses combos no game mat has

+0x1F0 vertex_format (u32)
    what each vertex in the mesh contains   has to match the mesh EXACTLY or it draws garbage
      b0   position
      b2-3   normal (b19, b23 also normal-related, unknown)
      b4-5   tangent (b24 = packed tangent)
      b6-7   bitangent (b25 = packed bitangent)
      b8   vertex color (COLOR0)
      b9-10   extra color sets (COLOR1) per vert blend amounts .r/.g/.b scale layers 1/2/3
      b11-13   number of UV sets (1-4)
      b16-17   skinning (weights + bone indices)
      b26   baked vertex lighting
    diffuse texture but no UV set in the format -> loader adds one, stride no longer matches mesh
    build records with >=1 UV set.

+0x0B4 texture_flags (u32)
    which features the material uses
      b0   normal map (surface_texture)
      b3   lit with vertex color + normal(about 2/3 of materials)
      b5   env map (envmap_texture)
      b6,7,8   layer 1,2,3 present
      b12   lightmap UV set (with lightmapped render_path)
      b13   vertex-fetch texture
      b14   vertex-fetch normal texture
      b15   shine map (shine_texture)
      b21   baked vertex lighting (goes with vertex_format b26)
      b31   second UV set in use

+0x26C shader_flags (u32)
    reencoding of texture flags  bits 0-14 are identical, the rest move
    (texture flags bit -> shader_flags bit):
      texflag b15 -> b15   only when a shine texture is set
      texflag b16 -> b30
      texflag b19 -> b16
      texflag b21 -> b31
      texflag b25 -> b20
      texflag b31 -> b26
    extra:
      b6-8   also enable the per-vertex COLOR1 blend for layers 1-3
      b12   skip light constants (same bit as texture flags b12, lightmap)
      b15   alt envmap scaling (same bit as texflag b15, shine)

+0x270 shader_flags2 (u32)
    lightmap/stencil variants
      b8   stencil variant
      b11   normal map
      b13   special pass
      b20,22   stencil

+0x268 input_defines (u32)
    extra shader key word. 0 almost always

UV set per texture slot (u8)
  1 = first UV set, 2 = second, etc.
+0x15C uv_lightmap   (u8)  default 1
+0x15D uv_surface   (u8)  normal map
+0x15E uv_specular   (u8)
+0x15F uv_layer1   (u8)
+0x160 uv_layer2   (u8)
+0x161 uv_layer3   (u8)
+0x162 uv_detail   (u8)

what each flag needs from vertex_format
(every game material obeys this, 0 exceptions)
  any diffuse texture   >= 1 UV set
  texflag b0 (normal map)   normal + tangent
  texflag b3   normal + vertex color
  texflag b5 (envmap)   normal
  texflag b8 (layer 3)   3 UV sets
  texflag b13-14 (vtf)   tangent + bitangent
  texflag b21 / shader_flags b31   present iff vertex_format b26

presets
(vertex_format / texture_flags / shader_flags / shader_flags2, uv_* all 1)
  standard   0x909 / 0x8 / 0x8 / 0   textured or plain color
  normalmap   0x929 / 0x9 / 0x9 / 0x800   + normal map
  envmap   0x909 / 0x28 / 0x28 / 0   + cube map
  skinned   0x28909 / 0x8 / 0x8 / 0   character meshes bent by bones
  skinned-normalmap   0x28929 / 0x1 / 0x1 / 0x800
  normalmap-envmap   0x929 / 0x29 / 0x29 / 0x800
  skinned-envmap   0x28909 / 0x28 / 0x28 / 0   no game material is this (TT only reflects on rigid parts)
  skinned-normalmap-envmap    0x28929 / 0x21 / 0x21 / 0x800   same


---drawing---

+0x040 render_state (u32)
  how it's drawn, default 0x3E160010
    b0-3   blend: 0 opaque, 1 alpha, 2 additive, 3 subtractive, 10 opaque with fixed alpha
    b10-11   texture addressing (wrap/clamp) for layers 0-3
    b12-13   is a cull: 0/1 back faces, 2 none (double sided, +0x2000)
    b14-15    depth mode
    b20-22   alpha test: <2 off, 5 = test against ref*2, other = on
    b23-30   alpha test reference

+0x044 flags (u32)
    default 0x10
    b22   cleared at load
    b23   unlit when it has no render bucket

+0x098 render_path (u32)
  default 0x9D00. byte +0x99 picks the draw path
    0x9D   normal
    0xAB   lightmapped
    0xA8   layered
    0x97   special

+0x09C unk_9c (u32)
  default 0xFF000000, low 24 bits non zero changes a render state

---layers---
layer 0 = texture x layer0_colour, layers 1-3 stack on top in order
each one blends against whatever's below it using layerN_blend

layerN color = its texture (uses uv_layerN) or layerN_colour if no textrue
strength = tex alpha x layerN_alpha x per vert value if you have it

blend (src is layer, dst is below)
  1 over      dst*(1-a) + src*a
  2 add       dst + src*a
  3 subtract  dst - src*a
  4 multiply  dst * (src*a + (1-a))

ertex_format b9-10 (+ shader_flags b6-8) adds a 2nd vertex color, and its .r/.g/.b fade layers 1/2/3, so you can fade a layer across a wall w/o a mask

only a small portion of game mats use layers, across 199 files, mostly level geometry
  layer 1 only 1916 (over 1583, add 373, multiply 115, subtract 55, ~25 something else?)
  layers 1+2 202
  layers 1+2+3 8, cutscene intros only
  layer colors always 0xFFFFFFFF, alpha usually 1.0
  per vert blend on ~790

all of this is settable with new-material, but meshes only get one UV set so uv_layerN has to be 1
theres no 2nd vertex color yet so no per vert layers
